# Test plan

## Executed coverage

The current C suite includes `test_deadlocklab.c`, `test_json.c`, `test_banker.c`, `test_experiment.c`, and `test_waitfor.c`; `make test` compiles with strict C17 warnings. The wait-for suite checks a deterministic two-process cycle, an acyclic chain, an immediately satisfiable request, rejection of a multi-instance model, and invalid requests. `tests/smoke_api.py` launches the real POSIX server and exercises health, fixtures, matrix detection, wait-for detection, termination, checkpoint rollback/preemption, Banker’s known safe sequence, versioned import round trip, seeded experiment repeatability, unknown routes, unsupported methods, missing/invalid/duplicate Content-Length, rejected Transfer-Encoding, wrong content type, payload-size rejection, embedded NUL, malformed escapes, duplicate JSON keys, and response-serialization overflow. GitHub Actions runs the C suite and live smoke on Ubuntu. `make sanitize` runs the core modules with AddressSanitizer and UndefinedBehaviorSanitizer.

The current Windows environment cannot link sanitizers or compile POSIX sockets: MinGW lacks ASan/UBSan runtime libraries and POSIX headers. WSL is available with elevated execution; current C, sanitizer, and live API suites have been run there.

Frontend checks cover scenario loading/editing, adding processes, API error display, trace navigation, editable Banker Max claims, versioned scenario import acceptance/rejection, read-only replay navigation that leaves active state intact, replay import validation (version, strict fields, sequence, accounting, detection trace, duplicate keys, and size limit), bounded experiment form validation, wait-for result and model gating, recovery confirmation cancellation, and API request/loading behavior. A manual narrow mobile viewport and keyboard-only walkthrough remain to be completed; reduced-motion CSS is present and enabled through the system preference.

`make test` compiles the C implementation with strict warnings and runs deterministic fixtures for empty/zero-allocation behavior, no deadlock, two-process deadlock, multiple instances, termination recovery, valid and invalid preemption, and nonnegative counts. Experiment tests compare 100 generated seeds against an independent detector, verify same-seed repeatability, and reject out-of-bound dimensions. The live smoke suite verifies the experiment endpoint returns identical outputs for repeat requests and preserves resource totals. It also compiles a test server with a 256-byte response cap and verifies oversized scenario serialization returns a structured HTTP 500 error. Recovery tests check post-transition resource accounting and rerun detection. GitHub Actions runs this on Ubuntu, which also compiles the POSIX server.

Frontend Vitest covers live API fixture loading, canonical matrix editing, process creation with correctly sized rows, API error display, and trace navigation. TypeScript checking and Vite production build run in CI.

Manual demo check: start C API, load the two-process fixture, run matrix detection and inspect its trace; analyze the wait-for graph and observe its single-instance assumption; terminate P1, confirm the updated state and empty deadlocked set; then load the multiple-instance fixture and use matrix detection. Check browser keyboard navigation and a mobile viewport. Future extensions should add JSON fuzzing, additional malformed HTTP request tests, recovery confirmation tests, keyboard and reduced-motion tests, and explicit responsive viewport checks.
